# CLK 3.0.3 Chain Map and Fusion Alignment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Do not use subagents unless the Owner separately authorizes them. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give CLK one clear structural authority, one shared model-selection authority, and one unambiguous Fusion code-ownership rule while preserving its existing nine-Skill architecture.

**Architecture:** Add `CLK-CHAIN-MAP.md` as a Supervisor-owned/readable-by-all Run artifact and template. Bind every Chain and Fusion to the same latest-SLK baseline selected for the Run, route all model choices through `$slk-select-models`, and make Fusion the sole owner of cross-Chain code integration in a new independent worktree; construction Chains never merge one another or become a hidden mainline.

**Tech Stack:** Markdown Agent Skills, Python 3 repository validation, JSON SHA-256 manifest, pytest.

---

## Fixed implementation boundary

- Keep exactly nine active CLK Skill directories.
- Do not create `clk-select-models`, Checker, Worker, dispatch, execution, D0, D1, D2, rework, communication, or patrol Skills.
- Add exactly one asset: `skills/chain-loop-skill/assets/CLK-CHAIN-MAP.template.md`.
- Keep `CLK-RUN-<RUN-ID>-RECORD.md` as the Run history/summary; it does not become the Chain structure authority.
- `CLK-CHAIN-MAP.md` is created and modified by the Supervisor and may be read by every member.
- Every Chain and Fusion uses the same Run-bound latest SLK baseline, including the SLK 3.0.3 CELL-continuity clarification.
