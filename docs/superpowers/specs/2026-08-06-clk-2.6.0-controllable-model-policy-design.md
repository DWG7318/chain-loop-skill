# CLK 2.6.0 Controllable Model Policy — Design

Date: 2026-08-06  
Status: Owner-approved implementation design  
Scope: CLK only

## Goal

Replace CLK's fixed, role-wide model assumptions with one fail-closed, versioned
model-binding policy. The policy selects a capability tier from work facts, records
the actual model and equivalence evidence, preserves role isolation, and requires a
new verified binding for every model change. It does not change fixed Chains,
ordered Levels, full Barriers, D0–D3, wake/progress/capacity behavior, or authority.

## Frozen decisions

1. `gpt-5.6-terra+xhigh` is the default for all canonical technical roles and for
   the separate non-authoritative Run patrol.
2. `gpt-5.6-luna+xhigh` is permitted only for a Worker executing a CELL whose
   current contract is explicitly `fine_grained=true` and `risk_class=LOW`, whose
   capacity gate passed, and whose selection reason is
   `FINE_GRAINED_LOW_RISK_CELL`.
3. `gpt-5.6-sol+xhigh` is permitted only for
   `HIGH_COMPLEXITY_CORRECTION`, `ROOT_CAUSE_DIAGNOSIS`, or `COMPLEX_REWORK`, with
   scoped evidence. It is not an ordinary implementation or checking default.
4. GPT 5.5 and lower are prohibited. `ultra` is prohibited unless the Owner gives
   item-specific authorization in the current Run. The normal required reasoning
   effort is `xhigh`.
5. A non-reference model is acceptable only when an immutable evidence record
   proves capability equivalence to the selected tier. Unknown or weaker
   equivalence fails closed.
6. Patrol gets no implicit low-cost exception. It follows the Terra default and
   remains outside the canonical technical-role enum and every D layer.

## Canonical artifact

Add one `MODEL_BINDING_LEDGER` schema/template/reference/validator. It contains:

- policy version and Run identity;
- current versioned CELL contracts needed for Luna eligibility;
- immutable capability-equivalence records;
- one explicit current binding per required technical actor and the unique patrol;
- actual model, provider/family, capability class, selection tier/reason,
  reasoning effort, scope, and content-hashed evidence;
- readiness, isolation, and verification receipts for each binding;
- explicit model-change records that connect old/new binding identities.

The ledger is the single machine-checkable source for model selection. Existing
receipts continue to carry `model_binding_id`; the new validator proves that this
identifier points to a valid, current ledger binding.

## Capability classes and selection tiers

| Tier | Reference binding | Eligible scope | Required facts |
|---|---|---|---|
| `DEFAULT_TECHNICAL` | `gpt-5.6-terra+xhigh` | Any CLK technical role | no exception reason |
| `DEFAULT_PATROL` | `gpt-5.6-terra+xhigh` | Unique Run patrol | non-authoritative patrol binding |
| `FINE_GRAINED_LOW_RISK_EXECUTION` | `gpt-5.6-luna+xhigh` | Worker + one CELL | fine-grained, LOW risk, capacity PASS |
| `HIGH_COMPLEXITY_CORRECTION` | `gpt-5.6-sol+xhigh` | Scoped technical role | high-complexity correction evidence |
| `ROOT_CAUSE_DIAGNOSIS` | `gpt-5.6-sol+xhigh` | Scoped technical role | root-cause evidence |
| `COMPLEX_REWORK` | `gpt-5.6-sol+xhigh` | Scoped technical role | complex-rework evidence |

`selection_tier` is a capability requirement, not a vendor name. A GPT reference
model satisfies its own tier. Another model must point to a content-hashed
`CAPABILITY_EQUIVALENCE` record whose target tier equals the binding tier and whose
result is `PROVEN_EQUIVALENT`.

## Binding invariants

- Canonical technical role kinds remain exactly `SUPERVISOR`, `CHECKER`, `WORKER`,
  and `VERIFICATION`; `PATROL` is validated separately.
- Every binding has a unique `binding_id`, concrete `actor_id`, current scope,
  actual model, reasoning effort, selection tier/reason, and evidence hashes.
- Required actors have exactly one `ACTIVE` binding. Superseded bindings are
  retained but cannot be used for current work.
- Luna requires a current CELL contract with matching Run/GO/CELL identity and all
  eligibility facts. Cost or convenience is never a legal selection reason.
- Sol requires one of the three allowed exceptional reasons and matching scoped
  diagnostic/rework evidence.
- Terra is the default. Terra used with an exception reason is rejected because
  it obscures the actual selection decision.
- Reference GPT bindings must use the exact model for the selected tier. Other
  models require proven equivalence. GPT 5.5 and lower fail before equivalence is
  considered.
- `xhigh` is required unless an item-specific Owner authorization permits `ultra`.
  Authorization binds Run, actor, scope, model, effort, and evidence hash.
- Every binding must have valid readiness, isolation, and verification evidence.
  Identical model families across roles remain legal only with distinct
  conversation, context, workspace, runtime namespace, binding, and evidence IDs.

## Model changes

A model change is never an in-place edit. It creates:

1. a new binding identity with a new reason and evidence set;
2. a `MODEL_BINDING_CHANGE` that names old and new binding IDs and the exact scope;
3. reciprocal `supersedes` / `superseded_by` links;
4. fresh readiness, isolation, and verification receipts for the new binding.

If one actor/scope appears under two actual models without this closed transition,
or if the old binding remains active, validation fails. Rework Round changes do not
by themselves authorize a model change.

## Integration points

- `clk-control-kernel.json` publishes the tier policy and switch invariant.
- `run-control-trace` changes only the patrol's default model to Terra and binds it
  to a model-binding ID; patrol runtime semantics stay unchanged.
- `role-isolation-and-verification.md` points model selection to the new ledger and
  retains all existing same-model isolation fields.
- Readiness keeps exactly 25 questions; an existing model/isolation question is
  expanded rather than adding questionnaire bloat.
- Repository validation includes the new schema/template/reference/validator and
  checks that legacy 5.5-or-lower positive guidance is absent from active assets.

## Rejected alternatives

- No per-role free-form model prose.
- No cost-based automatic downgrade.
- No fixed Luna patrol exception.
- No hidden in-place binding mutation.
- No new technical role, D layer, Chain, Level, Barrier, runtime, or message bus.
- No modification to SLK or GLK repositories.

## Acceptance

- Terra default, eligible Luna Worker CELL, eligible Sol exceptional work, and a
  proven-equivalent alternative all validate.
- GPT 5.5/lower, unapproved ultra, missing downgrade evidence, non-equivalent
  alternative, ordinary Sol, Luna outside Worker/eligible CELL, and silent switch
  fail closed in normal Python and `python -O`.
- Same-model role isolation remains machine-enforced.
- All existing 2.5.0 topology/runtime tests remain green.
- Repository/version/manifest/hash/template validators and Markdown budgets pass.
